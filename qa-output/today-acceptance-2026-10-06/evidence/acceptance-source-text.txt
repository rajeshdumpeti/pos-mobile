03 / Execution and evidence rules
Status Meaning
PASS All required checks executed and matched expected results. Identify founder-reported
versus independently inspected evidence.
FAIL At least one executed check differs from expected behavior. Record a defect.
PARTIAL Some checks passed but required checks remain untested or evidence is insufficient.
BLOCKED A prerequisite prevents safe execution. Record owner and unblock condition.
NOT TESTED Execution has not started.
Run one gate at a time during interactive founder testing. Each case below is independently recordable. All
positively phrased expected checks should be YES; use PARTIAL for any untested check. A screenshot
cannot prove request count, backend persistence, absence of scheduling or sensitive logging. Use redacted
network evidence when those assertions matter.
Evidence per run: case ID, timestamp/timezone, baseline, test-account alias, selected non-sensitive fixture
values, expected/actual result, screenshot or recording reference, sanitized request method/status/count and
relevant response fields, defect link and retest result. Do not capture passwords, verification codes, tokens,
Authorization headers, cookies, private email addresses or reset URLs.
