# Today Dashboard Core v1

Canonical backend delivery: `6bde40e0800ef36a9edefec9c6acbf5cc16d1e74`, Today contract `1.0`, `/api/v1`. Reviewed read-only sources: backend `docs/today-dashboard.md`, `docs/frontend-today-dashboard-handoff.md`, and `app/api/planning_schemas.py`. The committed OpenAPI snapshot is generated from that checkout's application; `npm run api:generate` refreshes types, `npm run api:check` checks drift. Runtime validation rejects malformed successful responses before state changes.

Today preserves the authenticated header, tabs, session and onboarding boundaries. It renders backend daily status, one recommendation/reason/CTA, reproducible score breakdown, unavailable measurements, ordered Up Next, explicit priorities and confirmed wins. Null is “No score yet”; zero stays 0%. The existing violet semantic theme replaces the reference's green accent. Nutrition, water, budget, workout and unsupported Quick Log actions are omitted. The visual-polish pass adds POS-owned decorative vectors, a continuous accent ring, and first-load motion with Reduce Motion support. Large text stacks columns and adjusts base heading/metric roles without capping text scaling. See [visual-polish delivery](today-visual-polish.md).

Explicit actions: `plan_item.create` opens Create; `plan_item.view` opens Detail; `plan_item.update` opens Edit; `plan_item.complete` opens Detail for deliberate confirmation. Domain identifiers never become routes. Add/Quick Log loads Today capabilities before exposing Create. All three new routes stay in the protected app stack; create/edit use standard native modal presentation (an iOS sheet) with a fixed header and safe footer. This avoids custom-detent form-sheet sizing that could hide the primary action when scheduling expands the form. Grouped controls cover title, friendly native date/time selection, priority and optional end time. New items use the valid device timezone; edits retain the item timezone. Timezone is not a normal editable field. Native wall-time selections become explicit-offset requests; repeated DST hours require a deliberate earlier/later choice. Switching scheduling off clears both timestamps. Offset roundtrips reject DST gaps; offsets distinguish repeated hours. Edit preserves fractional seconds.

Reads resolve device Intl timezone and send no computed date to Today. Explicit refresh, foreground, local-day or timezone change refresh reads. The 30-second timer compares only a local marker, not network polling. Confirmed content remains visible with a stale/offline notice on refresh failure, including a failed zone transition. Initial failure never becomes empty success. Queries have no automatic retries or reconnect refresh. Account-keyed providers cancel/remove feature queries and mutations and discard memory drafts on leaving an account; late writes cannot populate another scope.

Writes suppress duplicate taps immediately, use server versions and update only after validated confirmation. There are no optimistic wins/scores, mutation retries, reconnect replay, persisted drafts or queues. Creation freezes one payload/key; an ambiguous result preserves both for explicit retry. Changed intent requires explicit review/reset. State conflicts fetch current detail and require review; failed reconciliation cannot be acknowledged. 401 uses session clearing; onboarding 403 refreshes the existing session; other forbidden access clears it. Copy is frontend-owned; only sanitized request IDs and bounded retry metadata are shown.

## Founder acceptance setup

Use the canonical backend with a verified active account and completed onboarding. Configure the existing `EXPO_PUBLIC_API_BASE_URL`; never add credentials to source. Start Expo with the repository workflow, then sign in normally on iOS and Android. An authenticated backend/device session is required to verify real persistence; unit fixtures are synthetic and never imported by production screens.

1. Check light/dark, large text, VoiceOver/TalkBack headings, keyboard and modal focus/return. Confirm reference hierarchy and unavailable measurements.
2. Empty account: no score; create an unscheduled item from Today and Add. Reopen detail, edit title/date/priority, schedule with valid explicit offset, clear times and complete. Verify refreshed Today and wins only after confirmation.
3. Check score zero, mixed completion, all complete and breakdown arithmetic. Confirm backend timeline labels/order and priority membership.
4. Interrupt refresh: confirmed content stays marked stale; initial offline/error has retry and no fabricated data. Foreground/day/zone changes refresh reads only.
5. Simulate lost creation response, explicit identical retry, version conflict, missing/deleted item, rate limit, 401 and onboarding 403. Review latest item before resubmitting edits; review Today before new creation after ambiguity.
6. Sign out or change accounts during reads/writes; confirm no old content, draft or automatic write appears.

Android native inspection, real backend end-to-end writes, assistive-technology checks and founder visual approval remain manual acceptance requirements. Platform exports validate bundles, not native acceptance or staging readiness.
